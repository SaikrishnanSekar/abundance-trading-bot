What this system is

A dual-loop trading assistant for a live Dhan account (₹50,000, NSE intraday MIS + research-only swing scans). It never trades on its own. Deterministic Python scanners generate recommendations; every live entry needs an explicit human Y over Telegram; strategy rules can only change through a written proposal that a human commits.

The honest numbers (read this before expecting 3–4%/week)

On 15+ months of real NSE data, any Nifty-50 large cap touches +3% within 5 trading days only ~28% of the time, and no daily-bar filter tested (momentum, relative strength, volume, ATR, breakout, dip-buy…) beats that out-of-sample. A weekly 3–4% return is a target profile to select for, not a promise — currently only the intraday ORB sleeve has positive real-data expectancy (63.8% win rate in backtest, zero live trades logged yet). The journal

An append-only ledger (journal/india/*.jsonl). Records are immutable — the code has no update or delete path. Every record carries the ruleset version that produced it (currently 1.0.0), so evidence never mixes across rule changes.

  • At generation time: ticker, timestamp, entry price, the exact filter values that caused selection, target/stop/time-stop, regime snapshot.
  • After the window closes: max favorable/adverse excursion, exit reason (target / stop / time-stop), realized return — computed from official NSE bhavcopy. Missing data ⇒ the record stays open. Never estimated.
  • Conservative grading: if one daily bar touches both stop and target, the stop is counted first.

The feedback mechanism — five gates between data and rule changes

The loop tunes the strategy only when evidence forces it to. Weak evidence ⇒ silence. That is by design: a loop that churns rules on noise destroys edges faster than it finds them.

0/30 closed Gate 1 · Minimum sample. Nothing may even be drafted until 30 recommendations have closed under the current ruleset.
Status: DATA-COLLECTION MODE
Gate 2 · Statistical significance. A signal counts only if its with-vs-without hit-rate difference survives a two-proportion z-test (p < 0.05, ≥10 samples each side). “Three good weeks” is not evidence.
Gate 3 · Out-of-sample confirmation. The pattern must also win on historical data it was not derived from (walk-forward backtest vs the 28.1% base rate). Journal-derived alone is never enough.
Gate 4 · Human approval. The loop outputs a written proposal to STRATEGY-PROPOSALS.md; only a human commit to TRADING-STRATEGY.md makes it live. The ruleset version is bumped so Gate 5 can compare eras.
Gate 5 · Regression protection. After any change, the next 30 closed trades are compared against the old baseline. Underperformance raises a rollback flag — again as a proposal, never automatically.

Weekly cadence

Every Saturday 09:00 the scheduled task runs journal.weekly_report (hit rate vs the 3–4% target, expectancy, per-signal attribution → journal/reports/WEEKLY-*.md) and journal.feedback_loop (the gates above → a tuning proposal draft only if Gates 1–2 pass). Outcome records: 0 total, 0 closed.
