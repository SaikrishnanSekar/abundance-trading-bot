The headline — the system did not trade because Windows refused to start it

Not one live scan cycle ran during the 2026-08-07 session. logs/scan_all.log jumps straight from 2026-08-06 16:00 IST to 2026-08-07 16:39 IST — the scanner's next heartbeat came 39 minutes after the close, and its first line reads Feed: STALE | Entry window: CLOSED at 13:00 (now 16:39). signal_timeline.jsonl and recommendations.jsonl both held zero rows for the date before today's repair.

This was not a sleep/wake problem, which is what the 08-04 and 08-05 outages were. The box was demonstrably awake: KeepAwake ran at 08:55 and CatalystScan completed normally at 10:00. The scanners were awake-and-refused, which is a different failure and has a different fix.

Root cause — 0x800710E0 on exactly the four tasks that require AC power

Every market-hours task returned Task Scheduler result 2147946720 = 0x800710E0, "The operator or administrator has refused the request" — the code Windows returns when a task's conditions block it, not when the task itself errors. The correlation with the power condition is perfect, with no exceptions:

The two tasks that ran are precisely the two tasks without the battery condition. All four trading tasks carry DisallowStartIfOnBatteries = True and StopIfGoingOnBatteries = True. The machine was on battery across the session, so Windows refused to start them, then fired the deferred runs once it was back on AC — at 16:39, 18:39 and 22:39, all long past the 13:00 entry cutoff.

StopIfGoingOnBatteries is the more dangerous half of the pair: it means that even on a session that starts correctly on AC, unplugging the laptop mid-morning silently kills the scanner. That is a strong candidate for the 2026-08-05 11:00 outage, which was previously written up as an unexplained mid-session stop — same signature, same four tasks.

The fix is two flags per task and no code change: clear DisallowStartIfOnBatteries and StopIfGoingOnBatteries on PreMarket_0845, KotakFeed, ORB_Scan and MultiStrategyScan. This is a host/infrastructure change, not a strategy change, so it is recorded here and left for an explicit go-ahead rather than applied silently.

The uncomfortable part — the filter that was dropped yesterday would have caught this

rsi_overbought_entry was concluded recommend-drop at day 10 with a cumulative -₹926. Its rule: skip a long taken at RSI ≥ 80 that has no supporting catalyst. TECHM entered at RSI 82 with no catalyst logged — a textbook match. Re-running the engine against the repaired tape confirms it: control -₹687, treatment ₹0, delta +₹687, 1 skipped.

Worse: the outage is what triggered the conclusion. The nightly JournalUpdate ran at 20:30 on 08-07, while the tape was still empty, and logged (10 day(s), cumulative delta Rs-926) *** CONCLUDED ***. That tenth day was the zero-signal outage row. Without it the experiment stood at 9 days — still running, below min_days_before_decision. A blackout that produced no data nonetheless pushed a governance decision over its threshold, and it did so on the very day whose real tape contained the one trade the rule was built to catch.

Read honestly, this does not reverse the conclusion. Corrected for today, the experiment's cumulative moves from -₹926 to -₹239 — still negative, so recommend-drop still stands. What it does say is that the margin is much narrower than the headline number implied, and that the rule's one good day came from exactly the setup it was designed to catch. Worth remembering if the dimension is ever re-proposed after its cooldown.

Data-integrity note, stated rather than silently fixed: the rsi_overbought_entry.jsonl row for 2026-08-07 still reads n_total: 0, delta: 0. Verdict

The worst operational day of the trial, and the most cleanly diagnosed. Zero of forty scan cycles ran, and for once the cause is neither mysterious nor a code defect: four scheduled tasks carry an AC-power condition, the machine was on battery, and Windows refused them with 0x800710E0. The two tasks lacking that condition ran perfectly — a clean natural experiment. Two flags per task fixes it, and the same flags plausibly explain the 08-05 mid-session stop.

Financially the day cost -₹687 on a single reconstructed trade, TECHM, which was rejected by VWAP within ten minutes of entry. Cumulative v4 trial now -₹3,385 over 64 signals / 11 days, split LONG -₹990 (17/49) / SHORT -₹2,396 (6/15).

The analytical sting is that rsi_overbought_entry — concluded recommend-drop the day before — would have skipped this exact trade for +₹687. Its cumulative stays negative at -₹239, so the conclusion holds, but the margin is far thinner than it looked. Meanwhile TECHM is the first clean counter-example to yesterday's width finding: wide range, ideal volume, and it still lost, with RSI 82 the only dimension that called it.
