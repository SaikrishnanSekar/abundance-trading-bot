Data availability — read this first

Today's feed started clean and early (09:08 IST, before the 09:15 open — a big improvement on yesterday's 11:03 recovery). But the scanner (MultiStrategyScan) produced its last live cycle at 10:20 IST and never fired again for the rest of the day — no error, no crash trace, it just went quiet. This is a different incident from the scheduling bug fixed below: that bug (a fixed 3.5-hour repetition window) would have stopped the scan at 13:00-13:57 depending on start time, not 10:20. Something else — most likely the machine going idle/asleep mid-session — cut today's live monitoring short well before even the old buggy cutoff. The computer does not need to be on continuously for this to be recoverable, though — the Price Action Tracker tab fills the rest of each session from Yahoo Finance's 5-min bars (fetched after market close), so every recommendation below is followed all the way to its real target/stop/15:15-square-off outcome, not just to whatever the live scanner happened to catch. Only true real-time alerting and same-day trade execution actually require the machine to stay on through market hours — the tracker's postmortem accuracy does not.

Operational RCA — 4 findings today

All four are infrastructure/tooling issues, unrelated to strategy logic. No capital was at risk on any of them.

🔴

scripts/run_hidden.vbs was silently broken since ~May 8, killing 5 of 8 scheduled tasks

Root cause isolated via cscript (which surfaces errors wscript.exe //B was silently swallowing): the specific combination of variable name wsh + a preceding WScript.Arguments.Count check trips something on this machine (likely a script-monitoring/AV hook). Affected: KotakFeed, PreMarket_0845, ORB_Scan, TelegramPoll, NightlyHistoryFetch.

FIXED — switched to the plain CreateObject() function and renamed the variable. Verified end-to-end by re-firing PreMarket_0845 live: watchlist regenerated, Telegram sent.

🔴

run_kotak_feed.bat hardcoded a Python 3.11 interpreter missing neo_api_client

Separate bug from the vbs issue — explains why KotakFeed specifically kept dying even on a clean launch.

FIXED — repointed to the Python 3.12 install that has the package (same one used for both manual feed restarts this week).

🟠

MultiStrategyScan's fixed 3.5-hour repetition window silently truncated scan coverage every day

Trigger repeats every 10 min for a fixed PT3H30M duration, then stops — sized for a 09:30 start (→ stops 13:00), but the real trading session runs to 15:30. Any late start (like Monday's 10:27 login) shifts the whole window forward, cutting coverage even earlier (Monday's last cycle: 13:57). Even on a perfectly on-time day, 13:00-15:30 was never scanned at all.

FIXED — duration bumped to PT6H30M, comfortably covering the full session even from a late start. Takes effect from tomorrow's (2026-07-22) trigger onward — today's scan had already run under the old config before the fix was applied.

🟡

Scanner went dark at 10:20 IST today with no error — separate, still-open issue

Not explained by the duration bug (which would have allowed scanning well past 10:20 even under the old config). No crash trace in logs/scan_all.log. Most likely cause: the machine went idle/locked/asleep mid-session.

OPEN — needs to be observed live tomorrow to confirm whether the duration fix alone resolves coverage, or whether a separate always-on/wake-lock fix is also needed.
