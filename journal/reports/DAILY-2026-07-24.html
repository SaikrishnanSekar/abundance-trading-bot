logs/kotak_feed.log has not been written to since 2026-07-22 22:47:49 (its file modified-time, confirmed via stat) — no start banner, no ticks, nothing for 07-23 or 07-24. schtasks /query /tn "\TradingBot\KotakFeed" /v shows Last Run Time: 24-07-2026 18:55:49, Last Result: -2147020576, which decodes to 0x800710E0 — "The task is already running." KotakFeed's MultipleInstancesPolicy is IgnoreNew, so Task Scheduler refused today's catch-up launch because it believed a previous run (most likely the 2026-07-22 session, which never cleanly deregistered from Scheduler's bookkeeping even though its own log shows a clean "Feed stopped" line) was still active. A live process check just now (Get-CimInstance Win32_Process) found no kotak_feed.py process actually running — so whatever is "stuck" is inside Task Scheduler's own run-tracking, not a real zombie process consuming resources.

This explains 07-24 concretely and is a plausible explanation for 07-23 as well (same silent-log signature). Not yet fixed — recommend either changing MultipleInstancesPolicy to "Stop the existing instance" or clearing the run history via schtasks /end before each morning trigger.
