What happened — read this first

Compute wasn't available for most of today. The scanner ran cleanly on schedule from 09:30 (four full cycles: 09:30, 09:40, 09:50, 10:00 — one real recommendation, INDUSTOWER SHORT, fired at 10:01 IST). It then attempted a cycle at 11:27 that never completed (MultiStrategyScan's last recorded result today was a non-zero exit code) — consistent with the machine going offline mid-scan. Nothing ran again until this evening: both NightlyHistoryFetch and JournalUpdate caught up simultaneously at 22:47:38 IST (their scheduled 20:00/20:30 triggers, delayed by the same outage). That simultaneity caused a small race: journal.orb_autopsy checked for today's 5-min bars a moment before the concurrent history fetch had finished writing them, so its first automated pass reported INDUSTOWER as "no 5-min data yet." Data existed correctly by the time this session re-ran it manually (73 bars, full day 09:15-15:15) — INDUSTOWER is now graded.

Net effect: nothing is actually lost. The one real signal before the outage is fully graded and tracked. Whatever technically-valid ORB setups may have formed between ~11:30 and 15:30 today were never seen or journaled live (no Telegram alert, no recommendations.jsonl entry) — since the recommendation pipeline requires the live scanner to actually run and clear the gate at the time, a setup that only existed in that unmonitored window can't be reconstructed after the fact the way an already-journaled trade's price path can. That's a real (if modest, on a day like this) gap — distinct from, and smaller than, "the tracker couldn't resolve a real trade," which does not apply here.

NightlyHistoryFetch and JournalUpdate raced when both caught up at once

Both tasks were delayed by the same outage and their StartWhenAvailable catch-up fired them at the identical instant (22:47:38) tonight. orb_autopsy (inside JournalUpdate) read data/history_cache/ before the concurrent history fetch had finished writing today's bars, so its first pass under-reported. Manually re-run this session once the data existed — correctly graded INDUSTOWER as WIN, +0.99%.

Minor and rare (only manifests when both tasks are catching up from the same long outage simultaneously) — not fixed structurally, just worked around this time. Worth a small stagger between the two tasks' schedules if this repeats.
